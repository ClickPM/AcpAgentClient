## 0. 要解决的问题与本次裁定

agent 发来 `session/request_permission`（权限）或 `elicitation/create`（表单）之后就停下来等，用户不回应它就一直等。现在界面上只有**当前会话**的挂起请求看得见（画板 26 的停靠条只取当前会话的队列）。两处盲区：

1. **当前工作区里的后台会话**：它列在侧栏里，但条目上只有画板 06 的扫掠亮点线——而扫掠的意思是「正在干活」，恰好把「卡在等你」说成了「正在跑」。画板 06 D 表当时把这一格留成了「待裁定」，本次补上。
2. **别的工作区里的会话**：换工作区时它从会话区放下、也不再列在侧栏（侧栏只列当前工作区的会话），切换器上只有画板 08 C 的在跑数——它同样把等你的会话算作在跑。用户要切回那个目录、再点开那条会话才会发现。

本次裁定：

- **「等你处理」是一个独立的会话态**：该会话至少有一条挂起的 permission 或 elicitation（form 型与 url 型都算；url 型点过「打开」即算已回应）。认证阶段那种不带会话的 elicitation（走画板 52）不算。
- **与「运行中」互斥**：等你处理的会话**不扫掠、不计入在跑数**。挂起的请求全部了结（回应 / 被 agent 撤回 / 取消）而回合还没结束 → 回到运行中。
- **两处提示**：侧栏条目上一枚标记（§ 1 A 段，管当前工作区）；工作区切换器上一枚徽标（§ 1 B 段，按工作区汇总，含当前工作区）。
- **只提示，不代劳**：不自动切会话或切工作区、不弹窗、不置顶；画板 26 的停靠条仍只管当前会话，不改成跨会话。

### 1.4 反例块与小结
