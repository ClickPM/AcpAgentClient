## 0. 要解决的问题与本次裁定

registry 里的 agent 装好之后就停在装的那个版本：registry.json 里版本升了，面板上既不提示、也没有地方点升级。更糟的是，已安装条目名字旁的版本号显示的是 registry 的**最新**版本，装着旧版看着也像最新版。另外 registry 只在应用启动时拉一次，应用开着不会再检查。

裁定（所有者 2026-09-23）：

- **手动升级**，不做自动升级：条目上出 `Update` 按钮，用户点了才升。
- **可升级的判据**：本机安装记录里的 registry 版本 ≠ registry.json 当前版本。只判不等，不比大小。
- **新版本装在旧版旁边**，新版本首次握手通过后才切换；升级失败或取消，旧版本原样可用。
- **不打断正在运行的连接**：升级完成时该 agent 如果正连着，那条连接继续跑旧版，在会话头 `Reload Agent` 或重开应用后才换成新版。
- **提示只出现在 Agents 面板的条目上**：不加侧栏徽标、不加会话横幅、不加「可升级」过滤标签、不做「全部升级」。
- **检查时机**：启动时、打开 Agents 面板时（1 小时节流），外加标题行的手动「检查更新」。

## 1. 画板 50：改两处

frame 大小（1440 × 1005）与坐标都不变。

### 1.1 标题行加「检查更新」

标题行现在是 `ACP Registry  Agent Client Protocol 插件市场 …… Learn More ↗`。在 `Learn More` **左边**加两样，从左到右：

| 元素 | 规格 |
|---|---|
| 检查时间 | `检查于 12 分钟前`。样式同标题行副标题（`Agent Client Protocol 插件市场` 那一档）；相对时间的写法与侧栏会话项的 `15 分钟前` 一致 |
| 刷新按钮 | ghost 图标按钮，图标 lucide `rotate-cw`，尺寸与规格同画板 60 文件面板标题行的刷新按钮；悬停提示 `检查更新` |

两者之间、与 `Learn More` 之间的间距沿用标题行现有元素的间距。「检查中」那一态画在画板 53（§ 2.1），画板 50 只画空闲态。

### 1.2 Codex 那一行换成「可升级」态

列表第二行 Codex 改成：

- **版本**：`v1.11.0 → v1.12.0`。旧版本号与 `→` 保持现在的 muted 色，新版本号用强调色文字（同 `Learn More` 的文字色），同一档等宽小字。
- **芯片**：`已安装`（不变）后面追加 `可升级`，accent 色调（同画板 51 `installing` 芯片）。
- **右侧动作**：`Update`（primary，下载图标，规格同 `Install`）+ 其右的 `Remove`（不变）。两个按钮的间距同画板 51「安装失败」卡上 `重试` 与 `查看日志` 的间距。
- 描述、ID 行、源码仓库链接不变。

其余各行、过滤标签的计数（All 12 / Installed 3 / Not Installed 9）不变。

### 1.3 画板底部注释追加一句

在现有注释末尾追加：

`已安装条目名字旁的版本号是本机装着的版本；registry 有新版本时显示为「旧 → 新」。可升级 = 本机安装记录里的 registry 版本 ≠ registry.json 当前版本，只判不等、不比大小。`

## 2. 新增画板 53 · Registry 升级态

版式照搬画板 51：宽 1200，每个样张上方一行小标题，卡片的尺寸、内边距、图标位、标题行、描述、按钮、步骤列表、错误块全部沿用 51 的对应件。高度按实际内容定。

- 画板标题：`53 · Registry 升级态`
- 协议来源行：`协议来源：registry.json 的 version · agents/<id>/install.json（本地安装记录）`
- 四张卡（§ 2.2–2.5）都用 Claude Agent 作样张：已安装、已登录，旧版本 `v0.76.0`，新版本 `v0.78.2`，npm 包 `@agentclientprotocol/claude-agent-acp`。

### 2.1 标题行 · 检查中（顶部，通栏）

小标题：`Agents 面板标题行 · 检查中`

只画画板 50 右栏的标题行那一条，宽度与画板 50 的右栏一致，左对齐：刷新按钮换成 spinner（同画板 51 安装中那一只），时间文字换成 `检查中…`，其余同 § 1.1。

### 2.2 有新版本（第一行左）

小标题：`有新版本`

与 § 1.2 的 Codex 行同一套：版本 `v0.76.0 → v0.78.2`，芯片 `已安装` `已登录` `可升级`，描述照常，右侧 `Update` + `Remove`。

### 2.3 升级中 · npx（第一行右）

小标题：`升级中 · npx（新版本装在旁边，握手通过才切换）`

- 版本 `v0.76.0 → v0.78.2`；芯片只留一个 `upgrading`（accent，写法同 51 的 `installing`）。
- 步骤列表（样式同 51「安装中 · npx」），**两步**：
  1. `解析 npx 包 @agentclientprotocol/claude-agent-acp@0.78.2`（进行中，spinner）
  2. `首次拉起并握手 initialize`（未开始）

  没有「写入 settings.json」这一步：那一条在升级前就有，升级不动它。
- 步骤下面一行 muted 小字：`v0.76.0 仍可正常使用；新版本握手通过后才切换。`
- 右侧：spinner + `取消`（同 51）。

### 2.4 升级失败（第二行左）

小标题：`升级失败（旧版本不受影响）`

- 版本只写 `v0.76.0`（本机装着的那个）；芯片 `已安装` `已登录` `failed`（error，同 51）。
- 错误块（样式同 51「安装失败」），内容两行：
  - `npm error code ETIMEDOUT`
  - `npm error network request to https://registry.npmjs.org/@agentclientprotocol%2fclaude-agent-acp failed`
- 错误块下面一行 muted 小字：`升级到 v0.78.2 失败，仍在使用 v0.76.0。`
- 右侧：`重试`（primary）+ `查看日志`（同 51）。`重试` = 再升级一次。

### 2.5 已升级 · 待重载（第二行右）

小标题：`已升级 · 正在运行的连接仍是旧版`

- 版本 `v0.78.2`；芯片 `已安装` `已登录`（`可升级` 已消失）。
- 描述照常；描述下面一行 muted 小字：`已升级到 v0.78.2。正在运行的 v0.76.0 连接不受影响，在会话头 Reload Agent 或重开应用后生效。`
- 右侧：`Remove`（同已安装态）。
- 该 agent 的连接重连之后，这行小字消失，卡片回到 51 的「已安装」态。

### 2.6 画板底部注释

`只有 registry 型条目（npx / binary）检查与升级；custom 与内置条目不检查、不出 Update。状态优先级：升级中 > 升级失败 > 需要认证 > 有新版本 > 已安装——需要认证的条目有新版本时仍显示「旧 → 新」与「可升级」芯片，但右侧动作是「登录」，登录完才出 Update。binary 型升级的步骤就是 51「安装中 · binary」那三步（下载 → sha256 校验 → 解压，带进度条），下面加同一行「仍可正常使用」小字，不单画。升级取消后旧版本原样可用，卡片回到「有新版本」。registry 从没拉成功过时，标题行不显示检查时间，只留刷新按钮。`
