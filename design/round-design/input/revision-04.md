## 0. 要解决的问题

现在只有浅色。画板 00 的深色小节自己写着「本轮只备，不出深色页面画板」，里面只有 10 档中性色 + 一个 `d.accent`；实现侧照抄成 `tokens.dart` 的 `Dark` 类，但真实界面一处未用——只在内部色卡页展示过。

深色不是「把中性色反过来」。语义色的 soft 底、弹层表面、阴影、hover / active 叠色、代码高亮、终端 ANSI 这几处在深色下全部要重新给值，其中**叠色必须翻向**：现在是叠黑 6% / 10%，深色底上叠黑等于没有反馈。本次把这些一次定完。

**本次只出设计规格，不改实现。**

## 1. 命名总则（贯穿全文，实现依赖它）

浅色值在实现里是编译期常量，界面代码直接引用 token 名。深色要做成运行时可切的一套，前提是**深色值与浅色值按同一套 token 名一一对位**：一个浅色 token 名对应且只对应一个深色值，不新增、不合并、不拆分。

所以画板 00 的深色区**一律沿用浅色的 token 名加 `d.` 前缀**（已有的 `d.canvas` / `d.panel` … 就是这个规则）。举例：浅色 `accent.soft` → 深色 `d.accent.soft`；浅色 `semantic.error.soft` → 深色 `d.semantic.error.soft`。

**不允许**出现「深色专有、浅色没有」的 token，也不允许某个浅色 token 在深色区找不到对位值。§ 2 的对位表就是这个约束的全集，照表填满即可。

## 2. 画板 00：把深色补成完整一套

现有深色小节的标题「中性色阶 · 深色（本轮只备，不出深色页面画板）」改成「**中性色阶 · 深色**」，去掉括号里那句。下面按小节补。frame 宽 1440 不变，**高度不够往下加**（现在 900）。

### 2.1 中性色阶 · 深色：补 `d.strong`，`d.accent` 挪走

这一档现在是 10 个色卡，但和浅色对不上：浅色第 10 档是 `n.strong` `#1e1e26`（最重的文字色），深色这一档第 10 个放的却是 `d.accent`——**串位了**。

- 补 `d.strong`：深色下最重的文字色，比 `d.text` `#d5d5dc` 更亮（建议 `#f0f0f4` 一档，具体你定，要求与 `d.canvas` `#17171c` 对比度 ≥ 13:1）。位置在 `d.text` 之后，与浅色第 10 档对齐。
- `d.accent` 从中性色阶移到 § 2.2 强调色小节，改名 `d.accent.base`。

补完这一档是 10 个，与浅色 10 档逐位对齐。

### 2.2 强调色 · 深色：补 5 个

浅色 6 个值，深色只有 1 个。补齐：

| 深色 token | 对位浅色 | 浅色值 | 深色要求 |
|---|---|---|---|
| `d.accent.base` | `accent.base` | `#5566d8` | 已有 `#8b96ec`（原 `d.accent`），沿用 |
| `d.accent.active` | `accent.active` | `#3d4cb5` | hover / 按下。浅色是**变深**，深色下要**变亮**——方向相反，别照抄 |
| `d.accent.soft` | `accent.soft` | `#ecedfa` | 选中底 / info 底。深色下是一块低饱和深蓝，与 `d.surface` `#24242b` 要能分辨但不刺眼 |
| `d.accent.text` | `accent.text` | `#4a59c9` | 链接文字色，在 `d.canvas` 与 `d.panel` 上都 ≥ 4.5:1 |
| `d.accent.on-accent` | `accent.on-accent` | `#ffffff` | accent 底上的文字。深色的 accent 更亮，**白字可能不够**；该给深色文字就给，并标注理由 |
| `d.border.on-accent` | `border.on-accent` | `rgba(255,255,255,.45)` | accent 底上的 kbd 边框，跟着上一行的明暗走 |

### 2.3 语义色 · 深色：4 × 2 = 8 个

深色全缺。浅色的 soft 是**高亮度浅底**（`#fbeeea` 这类），深色下必须换成**低亮度深底**——不是把浅底压暗，压暗后色相会糊成灰。

| 深色 token | 对位浅色 | 浅色值 | 深色要求 |
|---|---|---|---|
| `d.semantic.error` | `semantic.error` | `#bc4e39` | 在 `d.canvas` / `d.panel` / `d.surface` 上都 ≥ 4.5:1 |
| `d.semantic.error.soft` | `semantic.error.soft` | `#fbeeea` | 失败卡底；与 `d.surface` 能分辨，且其上的 `d.semantic.error` 文字 ≥ 4.5:1 |
| `d.semantic.warning` | `semantic.warning` | `#8a6f12` | **浅色这个是深黄，深色下直接用必糊**，要显著提亮 |
| `d.semantic.warning.soft` | `semantic.warning.soft` | `#f7f2e2` | 同 error.soft 的要求 |
| `d.semantic.success` | `semantic.success` | `#477f40` | 同上；侧栏未读绿点也用它，6px 小面积要够亮 |
| `d.semantic.success.soft` | `semantic.success.soft` | `#ecf3ea` | 同上 |
| `d.semantic.info` | `semantic.info` | `#5566d8` | 浅色下 = `accent.base`；深色下也保持 = `d.accent.base` |
| `d.semantic.info.soft` | `semantic.info.soft` | `#ecedfa` | 浅色下 = `accent.soft`；深色下也保持 = `d.accent.soft` |

**对比度是硬要求**：8 个值各在色卡下写一个「在 `d.canvas` 上的对比度」数字。

### 2.4 三级表面 · 深色：3 个

| 深色 token | 对位浅色 | 浅色值 | 深色要求 |
|---|---|---|---|
| `d.surface.canvas` | `surface.canvas` | `#fbfbfc` | = `d.canvas` `#17171c` |
| `d.surface.panel` | `surface.panel` | `#f4f4f6` | = `d.panel` `#1d1d23` |
| `d.surface.popover` | `surface.popover` | **`#ffffff`** | 深色下弹层要**比 panel 亮一档**才浮得起来；与 § 2.5 的阴影一起定 |

边框两级不用补：`d.border.subtle` `#303039` 与 `d.border` `#43434e` 已在中性色阶里，与浅色 `border.subtle` / `border` 对位，宽度同为 1。

### 2.5 阴影 · 深色：1 个

浅色只有一条 `shadow.popover` = `0 4 12 rgba(28,28,35,.10)`。深色下黑影落在黑底上看不见，弹层会和背景糊在一起。给一条 `d.shadow.popover`，两条路线**二选一，不要两个都给**：

- A：加重的黑影（不透明度提到 .4~.5 一档、模糊加大）
- B：弱黑影 + 弹层顶部 1px 提亮内描边

选完在画板上写明选的是哪个、为什么。

### 2.6 叠色 · 深色：3 个（最容易漏的一条）

浅色的 hover / active 是**叠黑**：`overlay.hover` = `rgba(30,30,38,.06)`、`overlay.active` = `rgba(30,30,38,.10)`、`overlay.selected` = active。

深色下叠黑在深底上**等于没有反馈**，必须翻成**叠白**，且不透明度要重新定——白叠在深色上感知更强，照抄 6% / 10% 会过亮。

| 深色 token | 对位浅色 | 深色要求 |
|---|---|---|
| `d.overlay.hover` | `overlay.hover` | `rgba(255,255,255,.0X)`，X 你定 |
| `d.overlay.active` | `overlay.active` | `rgba(255,255,255,.0X)`，X 你定 |
| `d.overlay.selected` | `overlay.selected` | = `d.overlay.active` |

这一小节附一组**并排对照样张**：同一个 ghost 图标按钮的默认 / 悬浮 / 按下，左浅右深，证明两边的反馈强度看起来一致。

### 2.7 跟随派生的几项：确认一次，不新增 token

下面这些 token 的值是引用别的 token 的，深色下自动跟着走，**不需要新色卡**，但要在画板上各写一行确认：

- `focus.ring` → 跟 `d.accent.base`。焦点环 offset 1px 露出的是底色，检查在 `d.panel` 与 `d.surface` 上都看得见
- `kbd.border` → 跟 `d.border`
- `spinner.color` → 跟 `d.accent.base`
- `sweep.track` → 跟 `d.border.subtle`；`sweep.focus` → 跟 `d.accent.base`；**`sweep.focusGradient` 两端是 accent 的全透明版**（浅色实现里硬编码的是 `#5566d8` 的 alpha 0），深色下换成 `d.accent.base` 的全透明版——这一句要写在画板上
- `dot.unread` → 跟 `d.semantic.success`
- `timeline.rail` → 跟 `d.border.subtle`；`timeline.node` → 跟 `d.placeholder`

### 2.8 代码高亮 · 深色（新小节）

代码块的高亮主题是 27 个 scope 映射到 7 个 token：`accent.text`（关键字 / 字面量 / 内建）、`semantic.success`（字符串 / 正则）、`semantic.warning`（数字 / 类型 / 类名）、`n.placeholder`（注释）、`n.strong`（函数名 / 标题）、`n.text`（属性 / 变量 / 参数）、`n.muted`（运算符 / 标点 / meta）。

深色下这 7 个换成 `d.` 对位值后**要重新验一次**——尤其 warning（数字 / 类型）和 success（字符串）在深色代码底 `d.surface` 上最容易糊。

画板上画**同一段代码的浅色 / 深色并排样张**（用画板 13 里那段），7 类各标注用的是哪个 token。如果某一类换成对位值后不可读，**在这里改这一类的深色值**，不要回头去改 § 2.3 的语义色本体。

### 2.9 终端 ANSI · 深色（新小节）

嵌入式终端的 16 色 + 前景 / 背景 / 光标 / 选区 / 搜索命中现在全部从 token 派生（背景 = `n.panel`、前景 = `n.text`、光标 = `accent.base`、选区 = `accent.soft`、红绿黄 = 语义色、蓝紫 = accent 两态、黑白 = `n.strong` / `n.canvas`、bright 系列复用同色 + `n.muted`、搜索命中 = warning 两档 + `n.strong`）。

深色下换成 `d.` 对位值即可，**但要画一张 16 色色卡并排**（浅色在上、深色在下），确认 bright 系列与普通系列在各自底色上能分辨。

## 5. 不要动

- 除画板 00（深色区 + 新增的 2.8 / 2.9 两小节）、画板 70（加「外观」小节 + 深色样张）外，**不改任何现有画板**。
