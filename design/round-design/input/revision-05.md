## 2. B 段 · 回合折叠

### 2.1 「最终助手文本」的界定（收口）

一个回合里 agent 文本可能有好几段，穿插在工具调用之间。定为：

> **只有该回合最后一段连续的 agent 文本不折叠**；工具调用之间的中间 agent 文本**并进折叠块**，与思考块、工具卡同列。

「最后一段连续」= 从回合末尾往前数，直到遇上第一个非 agent-文本的块（思考 / 工具调用 / 终端 / 子代理 / 压缩）为止的那一段。

跟着改两处表格文字：

- 「折叠范围与例外」表里 `用户消息 / 最终助手文本 / 回合页脚 · 不折叠` 那一行，理由列改成：`结论与账单，永远直出；工具调用之间穿插的 agent 文本属于过程，进折叠块`。
- 「摘要行解剖」表里 `计数口径` 那一行改成：`条消息 = 本回合被折叠的块数（含思考块与中间的 agent 文本段）· 次工具调用 = tool_call 块数（失败与取消计入）`。

### 2.2 摘要行第二行的模型名（收口）

- **删掉**「摘要行解剖」表里 `换模型 / 回合内换过模型则显示「模型 A → 模型 B」，仍限一行 ellipsis` **整行**。

## 3. C 段 · 在跑数徽标

### 3.1 口径表改写（本次 C 段的实质改动）

原来的写法里，徽标只挂 `This Window` 的行，而 `Recent Projects` 里的工作区「恒无徽标（不去后台探活）」。问题是：**本应用一个窗口同时只开一个工作区**，`This Window` 恒只有一行 = 当前工作区。于是之前打开过、还有会话在跑的工作区全都落在 `Recent Projects` 里拿不到徽标，触发钮的合计就恒等于当前工作区的在跑数——而那件事侧栏的扫掠线（画板 06）已经在回答了。这张画板想解决的「切工作区前看不出别处还有活在跑」，按原口径恰好解决不了。

改法：

- **删掉** `未打开的工作区 / Recent Projects 里的工作区不常驻 agent，恒无徽标（不去后台探活）` 整行，换成：

| 问题 | 裁定 |
|---|---|
| 徽标挂在哪一行 | 本次运行里**打开过、内存里还有在跑会话**的工作区都挂，**不分 This Window 还是 Recent Projects**。这不是后台探活：换工作区只是把当前会话放下，它的 agent 连接还在本进程里活着，在跑与否我们本来就知道。本次运行从没打开过的工作区恒无徽标 |

- 在它之后**新增一行**：

| 问题 | 裁定 |
|---|---|
| 重启之后 | 应用重启后没有任何 agent 连接，所有徽标从零开始，不从磁盘恢复在跑状态 |

- 其余各行（`什么算「在跑」`、`数谁`、`触发钮的数字`、`排序`、`刷新`、`与侧栏的分工`）**全部不变**。

### 3.2 弹层样张改画

现在画的是 `This Window` 三行、其中两行带徽标。按 § 3.1 改成：

- **This Window：只有一行**——当前工作区 `…ariFlight_work\pi-cordis-toolbox`，选中态（accent 对勾 + accent 文字 + 按下态容器），徽标 `1`。
